# RDMA

学习RDMA（远程直接内存访问）可以按以下路径进行：

  基础概念                                                                                                              
  1. 理解传统网络 vs RDMA：先了解TCP/IP网络延迟的来源（内核切换、内存拷贝等），以及RDMA如何绕过这些问题                   2. 核心概念：学习RDMA三种传输模式（RC、UD、UC），以及QP（队列对）、MR（内存注册）、PD（保护域）等关键术语

  实践学习

  1. 从RoCE开始：推荐先学习RoCE（RDMA over Converged Ethernet），在数据中心更常用
  2. 使用rdma-core：这是最流行的用户态RDMA库，Linux原生支持

  推荐资源

  - 书籍：《RDMA Programming》- 入门友好
  - 官方文档：Mellanox/Intel RDMA文档（现在属于NVIDIA）
  - 开源项目：学习rdma-core的示例代码

  实验环境

  - 需要支持RDMA的网卡（ConnectX系列网卡便宜常见）
  - 或者用Soft-RoCE（软件模拟）进行学习



TCP/IP 网络延迟的主要来源

  1. 内核切换（Kernel Bypass）
```
应用 → 系统调用 → 内核 → 网络驱动 → 网卡
          ↑                      ↓
          ← ← ← ← ← ← ← ← ← ← ← ← 
```
  - 每次发送/接收数据需要从用户态切换到内核态
  - 一次完整IO可能需要多次上下文切换
  - 切换开销：约 1-5 微秒

  2. 内存拷贝

  用户缓冲区 → 内核缓冲区 → 网卡驱动缓冲区 → 网卡
     拷贝1       拷贝2          拷贝3
  - 数据在用户空间和内核空间之间多次复制
  - 每次拷贝：约 1-2 微秒/GB

  3. 协议栈处理

  - TCP/IP 协议栈在Linux内核中逐层处理
  - 包括：校验和计算、流量控制、拥塞控制、重传逻辑等
  - 每层都有处理延迟

  4. 中断驱动

  - 网卡收到数据后触发硬件中断
  - 中断处理需要保存上下文、跳转到中断处理程序

---
  RDMA 如何解决这些问题

  ┌──────────┬────────────────┬────────────────────────┐
  │   问题   │   传统TCP/IP   │          RDMA          │
  ├──────────┼────────────────┼────────────────────────┤
  │ 内核切换 │ 每次IO多次切换 │ 零拷贝，直接用户态访问 │
  ├──────────┼────────────────┼────────────────────────┤
  │ 内存拷贝 │ 4+次拷贝       │ 零拷贝，直接DMA        │
  ├──────────┼────────────────┼────────────────────────┤
  │ 协议栈   │ 内核处理       │ 硬件卸载，网卡处理     │
  ├──────────┼────────────────┼────────────────────────┤
  │ 中断     │ 频繁中断       │ 轮询模式，减少中断     │
  └──────────┴────────────────┴────────────────────────┘

  RDMA 的核心优势：让网卡直接访问用户虚拟内存，绕过内核
